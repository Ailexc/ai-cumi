# AiCumi 竞品调研报告 · 2026

> 调研时间：2026-08-21
> 调研目的：对比 AiCumi 当前实现与业界多 Agent 协作项目的功能差距
> 调研方法：GitHub 仓库分析 + 官方文档调研 + 功能矩阵对比

---

## 〇、一句话结论

**AiCumi 定位是"个人 AI 团队管理面"，与业界框架（AutoGen/CrewAI/LangGraph）不在同一赛道——它们是底层编排框架，AiCumi 是面向终端用户的产品层。** 但在产品功能层面，AiCumi 与同类产品（如 PraisonAI、OpenSquad、AgentFleet）相比，功能覆盖面约 40-50%，主要差距在：工具调用、记忆系统、可观测性、多模型支持、工作流编排。

## 三、详细差距分析

### 3.1 工具调用（差距：🔴 大）

**现状**：AiCumi 的技能系统只有目录和绑定，但 Agent 无法真正调用工具。

**业界标准**：
- AutoGen：`FunctionTool` + `AgentTool` + MCP 支持
- CrewAI：`crewai_tools`（搜索/代码/文件/API 等 50+ 工具）
- LangGraph：Tool Node + 自定义工具

**差距**：缺少 FunctionTool 注册、工具执行沙箱、工具结果注入对话。

### 3.2 记忆系统（差距：🔴 大）

**现状**：AiCumi 的记忆只是消息聚合，无向量检索。

**业界标准**：
- AutoGen：内置记忆组件
- CrewAI：短期记忆（会话）+ 长期记忆（SQLite）+ 实体记忆
- LangGraph：短期工作记忆 + 长期持久记忆 + 跨会话

**差距**：缺少向量数据库、Embedding 检索、记忆自动管理、跨会话记忆。

### 3.3 工作流编排（差距：🔴 大）

**现状**：AiCumi 只有简单的群聊路由（@提及 + 群主响应）。

**业界标准**：
- AutoGen：两 Agent 聊天、群聊、嵌套对话
- CrewAI：Flow（事件驱动 + 条件分支 + 并行执行）
- LangGraph：图编排（节点 + 边 + 条件路由）

**差距**：缺少任务分解、多步骤编排、条件分支、并行执行、工作流可视化。

### 3.4 Human-in-the-loop（差距：🟡 中）

**现状**：AiCumi 的用户只能通过聊天界面发消息，无审核机制。

**业界标准**：
- AutoGen：`human_input_mode` 参数
- CrewAI：`human_input` 任务配置
- LangGraph：中断/恢复机制

**差距**：缺少任务审核、中间结果确认、人类反馈注入。

### 3.5 可观测性（差距：🟡 中）

**现状**：AiCumi 只有基础审计日志。

**业界标准**：
- AutoGen：AutoGen Bench 基准测试
- CrewAI：AMP 控制台（追踪/监控/分析）
- LangSmith：执行路径可视化、状态转换追踪、运行时指标

**差距**：缺少 Agent 执行追踪、性能监控、调试工具、执行可视化。

### 3.6 文件/代码处理（差距：🟡 中）

**现状**：AiCumi 无文件上传/代码执行能力。

**业界标准**：
- AutoGen：Docker 代码执行
- CrewAI：文件工具 + 代码工具
- LangGraph：文件系统集成

**差距**：缺少文件上传、代码执行沙箱、文件分析。

### 3.7 已实现的优势

| 优势 | 说明 |
|------|------|
| **群聊路由** | @提及 + 群主值班响应，比大多数框架更贴近 IM 体验 |
| **人设系统** | 精修向导 + 模板库 + 持久化，比框架的角色定义更丰富 |
| **思考指示器** | 推理模型思考过程可视化，用户体验好 |
| **Web UI** | 三段式飞书风格布局，比 AutoGen Studio 更现代 |
| **消息持久化** | 完整的消息历史 + 多端同步 |

## 六、总结与建议

### 6.1 AiCumi 的独特价值

1. **群聊路由**：@提及 + 群主值班响应，比框架更贴近 IM 体验
2. **人设系统**：精修向导 + 模板库，比框架的角色定义更丰富
3. **思考指示器**：推理模型思考过程可视化
4. **飞书风格 UI**：三段式布局，现代感强
5. **消息持久化**：完整的历史 + 多端同步

### 6.2 关键差距

1. **工具调用**：Agent 只能聊天，不能执行实际任务
2. **记忆系统**：无向量检索，跨会话记忆断裂
3. **工作流编排**：无任务分解和多步骤协作
4. **可观测性**：无法追踪和调试 Agent 行为

### 6.3 建议路线图

```
阶段 1（2-3 周）：工具调用 + 记忆增强
  → Agent 能搜索、执行代码、调用 API
  → 跨会话记忆、向量检索

阶段 2（2 周）：文件处理 + 可观测性
  → 文件上传/下载/分析
  → Agent 执行追踪、调试工具

阶段 3（3-4 周）：工作流编排
  → 任务分解、多步骤协作
  → 条件分支、并行执行

阶段 4（2 周）：Human-in-the-loop
  → 任务审核、中间结果确认
  → 人类反馈注入
```
