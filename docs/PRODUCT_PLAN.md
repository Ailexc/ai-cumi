# AiCumi 产品方案 v0.1

> 状态：正式立项草案 ｜ 2026-08-16 ｜ 核心目标：**自有聊天通道 + 可视化管理面**，OpenClaw 做引擎。

---

## 一、产品定位

**个人云端 24/7 私人 AI 助理团队**。用户用**自己的聊天窗口**与一群 AI 员工协作（私聊/群聊），员工各有人设、技能、性格、说话方式；管理面"点一点"完成员工编排、技能绑定、渠道接入；后台保证稳定与多租户隔离。

> **交互基调（2026-08-16 修正）**：AiCumi 不是"AI 聊天工具"，而是"**你的 AI 同事团队**"。打开它就像走进办公室——侧栏是**团队成员**（可灵/小研/小文…），点谁就和谁聊；和每个成员的对话是**持续的**（像和同事的 IM），**没有"新建对话"这种机器范式**。底层 Room/Session 只是技术实现，产品层一律呈现为"人"。

## 二、解决的核心问题

1. **引擎太复杂**：OpenClaw 配置/管理页太繁琐，普通用户无法上手 → 需要**可视化管理面**把复杂度藏起来。
2. **依赖外部宿主 = 做嫁衣**：只桥接到飞书，用户停留在别人的产品里 → 需要**自有聊天通道**，让用户留在我们的产品。
3. **AI 生成人设质量不可控（听天由命）** → 需要**精修模板库 + 生成后可预览校验 + 迭代闭环**。
4. **稳定性不该是用户的事** → 云端托管，壳负责监控/重启/告警。
5. **把 AI 当机器的交互（违和）**：传统 Chat 工具的"新建对话/清空会话"范式把 AI 当工具，与"助理团队"定位冲突 → 采用**同事式交互**：成员列表即入口，对话持续，无"新建对话"概念（2026-08-16 修正）。

## 三、架构（核心：自有聊天通道 = 一等公民）

```
┌─────────────────┐  WS  ┌──────────────────┐ 自定义channel插件  ┌─────────────────┐
│  Web 聊天 UI     │ ⇄───│  聊天服务器（壳）  │ ⇄───────────────│  OpenClaw Gateway │
│  （私聊/群聊）    │      │  会话/房间/路由   │                  │  agent/记忆/工具  │
└─────────────────┘      └──────────────────┘                  └────────┬────────┘
                                                                可选: 飞书/Telegram/WhatsApp…
```

### 分层职责

| 层 | 拥有者 | 职责 |
|---|---|---|
| **管理面（壳）** | 我们 | 员工向导、技能编排、渠道配置、监控告警、租户/实例管理、计费 |
| **聊天服务（壳）** | 我们 | WS、房间/会话映射、@路由、消息持久化、多 agent 同群 |
| **Web Chat 通道** | 我们（协议客户端） | 用 gateway 原生 webchat 协议（chat.send/chat.history）直连；**不写插件**（引擎原生支持，见 §五） |
| **引擎** | OpenClaw | 多 agent 运行时、sessions_spawn、记忆、工具、cron、浏览器、模型路由 |
| **外部 IM** | OpenClaw 插件（可选） | 飞书/Telegram/WhatsApp/Slack/Discord 等接入 |

### 关键设计原则
- **交互 = 和同事交流，不是和工具对话**：侧栏是"我的团队"（成员 + 项目群），点成员直接进入其持续对话；**不做"新建对话/会话"包装**，底层 session 由系统延续（2026-08-16 修正）。
- **壳只写配置、只调稳定接口**（配置文件 + CLI + gateway HTTP/WS API），**不碰引擎内部** → OpenClaw 升级只做适配不崩。
- **Web Chat 与外部 IM 走同一套 agent 机制**（sessions/记忆/工具全复用）。
- 群聊路由参照现有飞书群聊逻辑**平移**（@agent → 对应会话；可灵被 @ 后可内部 sessions_spawn 调小研）。

## 五、技术要点与真相（已验证）

- **渠道硬约束**：OpenClaw 内置飞书 + 国际 IM（Telegram/WhatsApp/Slack/Discord/Signal/LINE/Zalo/Teams/Matrix/iMessage/IRC…），**无微信/QQ**（个人微信无官方 API，非官方桥接有封号风险）。
- **多租户**：OpenClaw 源码**无 multi-tenant 概念**，一个 gateway = 一套 agent/会话/workspace，天然不隔离。真隔离 = **每租户一个实例（容器）**；共享 gateway 做多租户会数据串，不可取。
- **聊天 UI**：开源组件可复用，简单；**聊天产品**（房间/会话映射/路由/历史）中等；**接入引擎**（自定义 channel 插件）是核心工作量。
- **OpenClaw 插件能力**：插件可加工具/模型商/通道/钩子/HTTP 端点/CLI/memory（已确认插件 manifest 支持 ChannelPlugin）。
