为什么需要工具调用

大语言模型本质是文本概率模型:它擅长推理与生成,但天生无法做到——访问实时信息、执行代码并拿到真实输出、读写文件、做确定性计算(比如"今天星期几")。没有工具,它只是聊天机器人;有了工具,它才成为能做事的 Agent。这就是工具调用在整个能力栈里的位置。

工具调用的核心范式是「声明意图,而不是执行」:模型不直接调用 Python 函数,而是输出一个结构化的 function_call 声明("我要调用 web_search,参数是 query=xxx"),由框架负责真正的执行,再把结果回填给模型,模型基于结果继续生成最终回复。三个角色的分工:

🎯 工具(能力提供者)

  • 一段真实可执行的函数 + 元数据(名称/描述/参数 schema)
  • 只负责"怎么执行",不决定"何时执行"

🧠 模型(决策者)

  • 阅读工具描述,自主决定"这个问题需要调用哪个工具"
  • 生成结构化 function_call,等待执行结果
能力无工具有工具
实时信息只能编造(幻觉)web_search 返回真实结果
计算/数据处理口算、易错code_execute 真实运行并拿输出
持久化产物只能输出文本file_write 落盘文件
确定性时间依赖训练数据,可能过时datetime_utils 精确取当前时间
学习要点:工具调用是「Agent 与外部世界交互」的通用协议。AiCumi 用 AG2 的 FunctionTool 作为执行原语,再用自研的 ToolRegistry 统一管理注册、元数据、绑定与开关 —— 前者来自框架,后者是产品层。

ToolRegistry 设计

ToolRegistry(backend/app/tools/registry.py)是一个全局注册表(tool_registry = ToolRegistry()),用三个数据结构 + 一组方法管理工具的全生命周期。

数据结构:ToolParameter 与 ToolDefinition

  • ToolParameter —— 参数定义:name / type(string|integer|float|boolean|array|object) / description / required / default / enum;
  • ToolDefinition —— 工具定义:name / description / category / parameters / func(真实函数) / enabled / version,提供两个序列化方法:
    • to_dict():给前端 API 的展示形状(不含 func);
    • to_openai_schema():生成 OpenAI function calling 风格的 JSON Schema(properties / required)。

注册:装饰器 + 签名推断

register() 是装饰器工厂:把函数包装成 ToolDefinition 存进 _tools[name]。没手写参数时,_infer_parameters() 用 inspect.signature() 从函数签名自动推断类型与必填:

def register(self, name, description, category="general", parameters=None):
    def decorator(func):
        tool_params = parameters or self._infer_parameters(func)
        self._tools[name] = ToolDefinition(
            name=name, description=description, category=category,
            parameters=tool_params, func=func,
        )
        return func
    return decorator

# 用法(builtin.py):
@tool_registry.register(name="web_search", description="Search the web ...",
                        category="search", parameters=[...])
def web_search(query: str, num_results: int = 5) -> str: ...

查询 / 开关 / 执行

  • 查询:get(name) / list_tools(category) / list_tool_names() / get_enabled_tools();
  • 开关:enable(name) / disable(name) —— 置 enabled 标志,执行与绑定前都会检查;
  • 执行:execute(name, **kwargs) —— 校验存在 / 启用 / 有实现后调用 func(**kwargs);
  • AG2 集成:get_ag2_tools(names) —— 见本章下文。
工具生命周期:定义 → 注册为元数据 → FunctionTool 包装 → 绑定 Agent → 运行时 execute 执行循环。

AG2 FunctionTool 集成

AG2 用 autogen_core.tools.FunctionTool 作为工具执行原语:它自动从函数签名生成 JSON Schema 发给模型,模型据此产出 function_call,框架调用函数并把结果回填。AiCumi 的 ToolRegistry.get_ag2_tools(names) 就是把内置工具批量包装成 AG2 工具的桥:

def get_ag2_tools(self, names=None) -> List[Any]:
    try:
        from autogen_core.tools import FunctionTool
    except ImportError:
        return []                       # AG2 不可用 → 空列表(mock 模式)

    target_tools = self._tools.values() if names is None else [
        self._tools[n] for n in names if n in self._tools
    ]
    tools = []
    for tool_def in target_tools:
        if not tool_def.enabled or not tool_def.func:
            continue                    # 禁用的 / 没有实现的跳过
        tools.append(FunctionTool(
            func=tool_def.func,         # 复用同一个函数对象
            name=tool_def.name,
            description=tool_def.description,
        ))
    return tools

  "description": "Search the web ...",

执行与安全

让模型能"执行代码、读写文件"意味着把系统能力交给了不可信的输入,安全设计是这一节的重点。

code_execute:子进程 + 超时 + 临时文件

def code_execute(code: str, timeout: int = 30) -> str:
    with tempfile.NamedTemporaryFile(mode='w', suffix='.py', delete=False) as f:
        f.write(code); temp_file = f.name
    try:
        result = subprocess.run(["python3", temp_file],
                                capture_output=True, text=True,
                                timeout=timeout, cwd=tempfile.gettempdir())
        os.unlink(temp_file)          # 用完即删
        return json.dumps({"success": result.returncode == 0,
                           "stdout": result.stdout, "stderr": result.stderr,
                           "return_code": result.returncode})
    except subprocess.TimeoutExpired:
        return json.dumps({"success": False,
                           "error": f"timed out after {timeout}s"})

三个护栏:子进程隔离(不注入主进程)、timeout 硬超时(默认 30s)、临时文件即用即删。错误统一转成 JSON 结构,让模型能"读懂"失败原因。

file_read / file_write:沙箱目录限制

workspace = os.getenv("WORKSPACE_DIR", os.getcwd())
abs_path = os.path.abspath(file_path)
if not abs_path.startswith(os.path.abspath(workspace)):
    return json.dumps({"error": "Access denied: File must be within workspace directory"})

所有文件操作先做绝对路径前缀校验,确保读写都锁死在 WORKSPACE_DIR 内;file_write 额外用 os.makedirs(..., exist_ok=True) 自动创建目录。

已知局限(刻意取舍):code_execute 用的是 subprocess 而非容器沙箱 —— 能防"失控进程",防不了"恶意代码读取工作区外路径";web_search 未配置 SERPER_API_KEY 时返回 mock 数据,不产生真实流量。生产级加固方向:Docker/nsjail 隔离、资源配额、命令白名单、审计回放。
学习要点:安全是"纵深防御"—— 路径前缀校验(入口)、子进程 + 超时(资源)、JSON 化错误(可观测)、沙箱目录(权限最小化)。面试讲工具调用时,主动讲安全设计是明显的加分项。

评分原则:功能完整性 × 实现深度 × 工程化 × 生产就绪度,1-5 星,参照对象是业界最主流的工具框架 LangChain Tools(以及 AG2 原生 FunctionTool)。
