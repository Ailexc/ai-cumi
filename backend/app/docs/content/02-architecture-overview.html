总体架构分层

AiCumi 是一个前后端分离 + Agent 引擎内嵌的单体后端架构：不依赖独立 Agent 服务，而是把 AG2 编排器跑在 FastAPI 进程内，通过 REST / WebSocket 对外服务。五层结构如下：

五层架构：前端 → API → 服务 → 引擎能力栈 → 存储。AG2 编排器内嵌于 FastAPI 进程（非独立 Agent 服务）。

为什么把 AG2 内嵌进程，而不是独立服务？

  • 学习项目取舍：单体便于调试与演进，一次 `docker compose up` 即起
  • AG2 的 gRPC Worker Runtime 已提供"进程内 → 跨进程"的平滑扩展路径（见 09 · 分布式）
  • 瓶颈可控：单用户个人项目，模型调用耗时远大于进程内编排开销

为什么消息走 WebSocket 而不是 SSE？

  • 双向能力：前端需要 `room.list / agent.list / group.create` 等控制面消息
  • 一套连接承载流式推送 + 指令下发 + 未读角标，协议统一
  • 实现参考 frontend/src/hooks/useChatSocket.ts

前端架构

前端分层：Workspace 壳 → Hooks（数据）→ 业务视图（导航切换）。文档详情用 Shadow DOM 隔离文档自身样式。

核心数据流：一次聊天

以「私聊 + 流式输出」为例，完整链路（对应 backend/app/main.py 的 /ws 处理器）：

私聊流式时序：记忆检索 → 模型流式 → 思考剥离 → 逐字推送 → 持久化 + 记忆回写。
  1. 前端发送：`chat.send`（WS）携带房间与内容，可选 knowledge_scope 触发 RAG 注入。
  2. 记忆检索：build_memory_context() 用向量检索相关长期记忆，注入 system 上下文（`chat.memory` 事件展示给前端）。
  3. 模型流式：AG2 AssistantAgent.on_messages_stream() 逐 token 产出。
  4. 思考剥离：剔除 <think> 标签 / AG2 reasoning 前缀，只推最终回答（`chat.thinking` 指示器）。
  5. 流式推送：chat.chunk 逐字转发，前端打字机渲染。
  6. 收尾：chat.done 携带完整内容；消息落库（SQLite）+ 对话写入长期记忆。

架构演进：OpenClaw → AG2

2026-08-20 决策：从「壳层产品思路」转向「自研学习作品」，弃用 OpenClaw、全量迁移 AG2。
